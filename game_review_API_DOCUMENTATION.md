# ChessLensAI - Game Review Implementation & API Docs

This document provides everything the Mobile Developer needs to implement the Game Review feature using the **Flutter Stockfish Package** locally, minimizing server costs.

---

## 1. Local Stockfish Implementation (Flutter Side)

To process the game locally on the device, follow these exact algorithms translated from the backend's `review_logic.py`:

### A. Convert Centipawns to Win Probability (WP)
Chess.com doesn't classify moves based on flat centipawn drops. It converts the evaluation to a "Win Probability" percentage first. 
*Note: Ensure mate scores are capped (e.g. +/- 10000).*

**Constant:** `WP_CONSTANT = -0.00368208`

**Formula:**
```dart
double evalToWp(int cp) {
    // cp is centipawns from White's perspective
    int cappedCp = cp.clamp(-10000, 10000);
    return 50 + 50 * (2 / (1 + exp(WP_CONSTANT * cappedCp)) - 1);
}
```

### B. Calculate Win Probability Loss
For every move, calculate the `wp_loss`:
```dart
// For White:
double wpLoss = wpBefore - wpAfter;

// For Black:
double wpLoss = (100 - wpBefore) - (100 - wpAfter);

// Never allow negative loss
wpLoss = max(0.0, wpLoss);
```

### C. Move Classification Thresholds
Classify the move based on the `wpLoss` calculated above:
1. **Miss**: If the player had a forced mate (eval > 9000) before the move, but LOST the forced mate after the move.
2. **Best**: `wpLoss <= 2.0`
3. **Excellent**: `wpLoss <= 5.0`
4. **Good**: `wpLoss <= 10.0`
5. **Inaccuracy**: `wpLoss <= 15.0`
6. **Mistake**: `wpLoss <= 30.0`
7. **Blunder**: `wpLoss > 30.0`

*(Note: Brilliant and Great moves require deeper heuristics, you can default them to 0 for the MVP).*

### D. Accuracy Calculation
To calculate a player's overall accuracy, use the exponential decay formula based on their *average* WP loss across the whole game.

**Constant:** `k = 0.05`

**Formula:**
```dart
double accuracy = 100 * exp(-0.05 * averageWpLoss);
```

## 2. API Endpoint for AI Summary

Once the Flutter app has finished the local evaluation and tallied up the stats using the logic above, you send the final tallies to the backend to get a 2-4 sentence narrative review generated by the Groq LLM (as defined in `review_service.py`).

**Endpoint:** `POST /api/review-summary`

**Request Payload:**
```json
{
  "payload": {
    "opening": "Queen's Gambit Declined",
    "result": "White",
    "players": {
      "white": {
        "brilliant": 1,
        "great": 0,
        "best": 20,
        "mistake": 2,
        "miss": 0,
        "blunder": 0,
        "accuracy": 94.2
      },
      "black": {
        "brilliant": 0,
        "great": 0,
        "best": 15,
        "mistake": 4,
        "miss": 1,
        "blunder": 2,
        "accuracy": 72.1
      }
    },
    "critical_mistake": {
      "move_number": 18,
      "player": "Black",
      "classification": "Blunder",
      "reason": "Critical Blunder",
      "played_move": "Nd4",
      "engine_recommended_move": "Nf6",
      "fen": "r1b1kbnr/pppp1Npp/8/6q1/2BnP3/8/PPPP1PPP/RNBQK2R b KQkq - 0 5"
    },
    "notable_good_move": {
      "move_number": 21,
      "player": "White",
      "classification": "Great",
      "played_move": "Rxf7+"
    }
  }
}
```

**Response Payload:**
```json
{
  "summary": "White played a solid Queen's Gambit Declined and capitalized on Black's mistakes. The turning point came on move 18 when Black blundered with Nd4 instead of the recommended Nf6. White's consistent play secured the win."
}
```

## 3. Alternative: Full Server-Side Evaluation
If for some reason the Flutter Stockfish approach fails or takes too long on older devices, you can fall back to sending the raw PGN to the backend and letting the server do all the math.

**Endpoint:** `POST /api/review`

**Request Payload:**
```json
{
  "pgn": "1. e4 e5 2. Nf3 Nc6..."
}
```

**Response Payload:**
*Returns a massive JSON object containing the stats, accuracy, opening, `moves` array (with every evaluation), the `eval_graph` array, and the AI `summary` text.*
